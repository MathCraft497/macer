# 常见问题（FAQ）

## Q1：为什么用 Python 作为后端而不是 LLVM？

Python 后端让编译器实现更短、更易读，适合学习与快速原型。
要替换后端，只需重写 `codegen.py`，前端完全复用。

---

## Q2：为什么错误信息里看不到 Python 异常？

编译期所有错误经 `MacerCompileError` 抛出并被 `Compiler.compile_source` 捕获；
运行期通过 `../src/macer/runtime/runtime.py` 的 `__macer_wrap__` 把 Python 异常翻译为 `MCE4xxx` 诊断。

因此用户永远只看到 Macer 风格的错误。

---

## Q3：`Any` 会不会破坏类型安全？

`Any` 与任意类型可互相赋值，是逃生口。推荐只在必要时
（如与动态数据交互）使用。

---

## Q4：`import` 目前能跨文件吗？

语法可解析，但**模块加载未实现**。当前只支持单文件编译；
多文件请合并或扩展 `Compiler`。

---

## Q5：`init` 里为什么不需要显式调用父类构造？

`CodeGen.gen_ctor` 会在用户 init 体之前自动插入
`Parent.__init__(self, ...)` 调用，并把父类构造参数按名称转发。

---

## Q6：如何开启/关闭颜色？

默认在 TTY 下启用；`--no-color` 或管道输出时自动关闭。

---

## Q7：能否给出错误码的完整列表？

见 [错误码表](error-codes.md)。

---

## Q8：编译器自身报错怎么办？

理论上不会。`Compiler.compile_source` 有 `except Exception` 兜底，
会把任何内部错误也转成 `MCE4099`，不会泄露 Python traceback。

---

## Q9：如何扩展语言？

见 [贡献指南](contributing.md)。

---

## Q10：运行 `run` 生成的 `.__macer__.py` 是什么？

是编译器转译出的 Python 中间产物，会放在 `.mce` 文件同目录。
可安全删除，下次运行会重新生成。

---

## Q11：需要虚拟环境吗？

不需要。Macer 只用 Python 标准库，不安装任何 pip 包。

---

## Q12：会不会污染 Python 环境？

不会。删掉整个 `macer/` 目录就等于卸载完毕。

---

## Q13：支持泛型吗？

当前版本**不支持**。词法和语法层预留了泛型括号 `<...>` 的解析，
但类型检查未实现。计划在后续版本加入。

---

## Q14：支持接口 / trait 吗？

当前版本**不支持**。可通过抽象基类 + 覆盖方法模拟。

---

## Q15：`main` 是必须的吗？

不是。如果源文件中没有 `main` 函数，编译器不会生成入口调用；
你可以把 Macer 当作库，由其他代码调用其顶层函数。
